# 02 — Architecture

## Monorepo (pnpm workspaces, TypeScript strict, Node 22)
```
er-trade-calc/
├─ packages/
│  ├─ engine/        pure functions. No I/O. Builds + data in → results + breakdown out.
│  │   src/assumptions.ts   the single assumptions file (docs/09)
│  │   src/stats/           effective stats, RL math, 2H rule, requirements, equip load
│  │   src/ar/              weapon AR per damage type (wraps/ports Tom Clark's MIT calculator logic)
│  │   src/hit/             hit packets, modifiers, defence, negation, damage per type
│  │   src/attacks/         attack → list of hits (weapon hits, projectiles, buffs applied after)
│  │   src/interaction/     poise, stagger, HA/SA, trade resolution, timing, input delay
│  │   src/duel/            duel state, conditions (full HP etc.), hits to kill
│  │   src/sweep/           RL sweeps, matchup matrices
│  │   src/legality/        ERPvP ladder ruleset checks (fixtures/ruleset)
│  │   src/explain/         step-by-step breakdowns, assumption lists, credit footer
│  ├─ data/          one-time copy (docs/05) → raw (committed, checksummed) → build → typed bundle per patch
│  │   raw/emilia/<patch>/  Emilia's files, copied ONCE (committed)
│  │   gen/<patch>/  normalised data the engine loads (committed, regenerated by script)
│  ├─ builds/        importer for Emilia's planner build export JSON → engine Build (zod-validated)
│  ├─ cli/           `ertc` command
│  ├─ mcp-server/    MCP server: stdio (local) + Streamable HTTP (Railway)
│  └─ discord-bot/   PHASE 2 ONLY. Do not create in phase 1.
├─ fixtures/        golden tests, ruleset, builds (from this package)
├─ docs/            spec (this package) + docs/public/formulas.md (public guide)
└─ .github/workflows/ci.yml
```

## Tooling
- **pnpm** pinned in root `package.json` `"packageManager": "pnpm@12.18.0"`. `.nvmrc` = `22`.
- **TypeScript** strict, ESM. **vitest** for tests. **zod** for validating builds and data. **tsx** for scripts.
- CLI: a small arg parser (commander or cac). Output: human tables by default, `--json`, `--breakdown`.
- MCP: official `@modelcontextprotocol/sdk`. Transports: stdio and Streamable HTTP.
- No Python, Docker or conda needed.

## Engine data flow (one hit)
```
Build A ─┐                                   ┌─ Build B (defender of this hit)
         ▼                                   ▼
 effective stats → weapon AR per type → + flat buffs → × MV per type → × attacker modifiers
                                                         │
                                defence per type (RL + stat) & negation (armour by phys type × other negations)
                                                         ▼
                          per type: A × curve(A/D) × (1−armour) × Π(1−neg) × PvP final rate → Σ → floor
```
Then the interaction layer uses the same hit (poise damage, startup, HA/SA) to decide trade / no trade.

## Hosting (Railway — Zer0 already pays)
- Railway project **er-trade-calc**, service connected to the GitHub repo, branch `main`, auto-deploy on push.
- Variables already set: `GAME_PATCH=1.17`, `NODE_ENV=production`. Railway sets `PORT`.
  `PUBLIC_URL` is added by Zer0 after the first successful deploy (Railway generates the domain then).
- Healthcheck path `/health` — must return 200 only after data is loaded and the engine self-test passes.
- Start command runs the MCP HTTP server. Provide `railway.json` (or `railway.toml`) with build + start + healthcheck.
- **No CDN caching** (MCP is POST + streaming). Data is loaded into memory at startup (attack data is ~18 MB raw; fine on Railway).
- Phase 2: the Discord bot runs on the same Railway project as a second service.
